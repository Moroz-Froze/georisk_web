# ГеоРиск · Linux + Docker · 1.5.0

Сборка FastAPI + React/MapLibre для Linux-сервера с Docker Engine и Compose v2. Адрес сайта задаётся позднее через `.env`; в приложении не закреплён домен Windows/IIS. Готовый интерфейс, три расчётные библиотеки, GeoPackage/GeoTIFF/ZIP и личные временные сессии включены. Python/GDAL находятся в контейнере; Node.js и QGIS на сервере не нужны.

## Запуск без выбора домена

Распакуйте архив в отдельную папку на сервере и выполните:

```sh
cp .env.example .env
docker compose -p georisk config --quiet
docker compose -p georisk up --build -d
docker compose -p georisk ps
curl --fail http://127.0.0.1:8000/api/health
```

Нужны работающий Docker Engine с Linux-контейнерами, Compose v2 и интернет для первой сборки. Если учётная запись не имеет доступа к Docker, команды запускает администратор через `sudo`. Это комплект для сборки образа, не готовый офлайн-образ Docker. [Установка Docker на Ubuntu](https://docs.docker.com/engine/install/ubuntu/).

По умолчанию порт доступен только на самом сервере: **127.0.0.1:8000**. Для проверки с своего компьютера до подключения домена откройте SSH-туннель:

```sh
ssh -L 8000:127.0.0.1:8000 user@server
```

Затем откройте **http://localhost:8000/** в своём браузере. Если локальный порт занят, используйте `-L 8010:127.0.0.1:8000` и адрес localhost:8010. Запущенный контейнер продолжает работать после закрытия SSH/выхода администратора. `restart: unless-stopped` запускает его после перезагрузки, когда запущен Docker; на сервере проверьте автозапуск самого Docker через `systemctl is-enabled docker`.

## Когда станет известен адрес

В `.env` укажите реальные значения. Например, для отдельного домена:

```dotenv
GEORISK_ALLOWED_HOSTS=hazards.example.org,127.0.0.1,localhost
GEORISK_PUBLIC_ORIGIN=https://hazards.example.org
GEORISK_BASE_PATH=
GEORISK_COOKIE_SECURE=1
```

В `GEORISK_PUBLIC_ORIGIN` задаётся только origin без пути. Для адреса вида `https://example.org/georisk/` дополнительно задайте `GEORISK_BASE_PATH=/georisk`. Домен/порт в origin должны точно совпадать с адресом браузера; Host-список содержит только имена/IP без схем и портов.

Настройте существующий HTTPS-прокси на порт 127.0.0.1:8000. Примеры для Nginx:

- `deploy/linux/nginx-root.conf.example` — приложение в корне домена;
- `deploy/linux/nginx-subpath.conf.example` — приложение в `/georisk/`, с удалением этого префикса при передаче в контейнер.

Выберите один пример. Замените example.org, пути сертификата и, при необходимости, порт/подпапку. Включение HTTPS, DNS и сертификата выполняется после выбора домена. Не заменяйте существующую конфигурацию остальных сайтов целиком; проверьте итоговый конфиг командой `nginx -t` перед применением. Допускается другой обратный прокси с теми же правилами Host/Origin, prefix и forwarded-заголовков.

**Укажите реальный IP прокси, видимый контейнеру**, в `GEORISK_TRUSTED_PROXIES`. Nginx на Linux-хосте обычно виден как шлюз Docker-сети, а не 127.0.0.1. Найти шлюз запущенного приложения:

```sh
docker inspect --format '{{range .NetworkSettings.Networks}}{{.Gateway}} {{end}}' "$(docker compose -p georisk ps -q georisk)"
```

Добавьте этот адрес к `127.0.0.1` в `.env`, например `GEORISK_TRUSTED_PROXIES=127.0.0.1,172.18.0.1`, **используя фактический адрес вашего сервера**. Если прокси работает в другом контейнере, задайте его реальный адрес или специально выделенную доверенную proxy-сеть. Значение `*` использовать нельзя. Прокси должен перезаписывать X-Forwarded-For адресом клиента, а не принимать его из браузера. Это нужно в том числе для корректных лимитов сессий по IP.

Примените настройки без пересборки интерфейса:

```sh
docker compose -p georisk up -d
```

Проверьте публичную страницу, карту, расчёт и выгрузку GeoPackage, а также работу после выхода из SSH. Не переопределяйте `Referrer-Policy` значением `no-referrer`: OpenStreetMap требует источник веб-запроса. В приложении используется `strict-origin-when-cross-origin`, передающий внешнему сервису только origin.

## Данные и ресурсы

- Приложение выполняется под UID/GID **10001:10001**, с read-only корнем контейнера. Приватные данные находятся в отдельном Docker-томе `georisk-data`, подключённом к `/data`; временные файлы — в ограниченном tmpfs `/tmp`. Приложению не нужны права root, Docker socket или привилегированный режим.
- У каждого профиля браузера отдельная временная сессия. Вкладки одного профиля разделяют сессию. Выход отменяет свои задания и удаляет загрузки/результаты; последняя закрытая вкладка запускает очистку через 15 секунд, потерянная сессия истекает после 10 минут без связи. При аварийной остановке остатки временных сессий очищаются при следующем старте. Скачанные пользователем файлы остаются у него.
- Один расчёт одновременно; общая очередь до восьми заданий. По умолчанию общая квота CPU — **0.5 логического ядра**, жёсткий лимит RAM — **2 ГиБ**, swap контейнера не добавляется. GDAL-кэш — 64 МиБ на процесс, вычислительные потоки — по одному; временный tmpfs 512 МиБ тоже учитывается в памяти контейнера.
- Параметры `.env`: `GEORISK_CPUS`, `GEORISK_MEMORY_LIMIT`, `GEORISK_GDAL_CACHE_MB`, `GEORISK_PORT`. Значение 2g — ограничение, не гарантия расхода: большой расчёт может закончиться ошибкой при нехватке RAM. Измерьте нагрузку на своих данных; изменение лимита не меняет формулы или разрешение расчёта. Ограничения ресурсов должны поддерживаться Linux/cgroups вашего сервера.
- Исходящий HTTPS нужен автоматической загрузке рельефа, спутников и погоды, а также картографической подложке в браузере. Выход на внешние источники зависит от сети сервера и доступности сервисов.

```sh
docker compose -p georisk logs --tail=100 georisk
docker stats --no-stream "$(docker compose -p georisk ps -q georisk)"
docker compose -p georisk exec georisk python -c "from osgeo import gdal; print(gdal.VersionInfo(), gdal.GetCacheMax())"
```

Заданный лимит RAM/CPU не распространяется на первую сборку образа. Приложение не обещает завершение произвольного участка за фиксированное время; таймер задания остаётся 30 минут.

## Обновление и обслуживание

```sh
# Остановка; Docker-том не удаляется, рабочие сессии закрываются приложением.
docker compose -p georisk down
# Сборка с актуальными системными пакетами и запуск новой версии.
docker compose -p georisk build --pull --no-cache
docker compose -p georisk up -d
```

При обновлении сохраняйте свою `.env` и прежнее имя Compose-проекта. Не используйте `down -v`, если намеренно не удаляете Docker-том. Не запускайте несколько экземпляров/несколько Uvicorn workers на одну папку данных. Перезапуск приложения завершает временные сессии; длительное хранение результатов на сервере в эту схему не входит.

База образа — Debian trixie-slim с системными Python/GDAL/NumPy; зависимости FastAPI закреплены в requirements. Нативные библиотеки и образ требуют обновлений и проверки на целевом сервере; известные замечания предыдущего аудита к HDF4/netCDF не объявляются устранёнными только сменой образа. Внешние растры приложения ограничены драйвером GTiff. Для публичной эксплуатации нужны HTTPS, настройки Host/Origin, лимиты запросов, свободное место и серверная квота диска. У сценарных моделей сохраняются научные ограничения: результат не заменяет инженерные изыскания.

Итоги и границы проверки этого выпуска — `LINUX_DOCKER_VERIFICATION.md`. [Параметры Compose](https://docs.docker.com/reference/compose-file/services/), [ресурсные ограничения Docker](https://docs.docker.com/engine/containers/resource_constraints/).


## Репозиторий и исходники интерфейса

Это актуальная Linux/Docker-версия GeoRisk в основном репозитории `georisk_web`. Серверные модули и расчётные библиотеки опубликованы вместе с готовым интерфейсом; редактируемые исходники React находятся в `webapp/frontend/src`, иконки — в `webapp/frontend/public`. Проверенный установочный ZIP и SHA-256 доступны в [релизе v1.5.0](https://github.com/Moroz-Froze/georisk_web/releases/tag/v1.5.0).

Для изменения интерфейса установите подходящий Node.js (22.12+ или 24+), затем:

```sh
cd webapp/frontend
npm ci
npm run test:unit
npm run build
```

После изменения интерфейса пересоберите Docker-образ из корня проекта. Docker использует `webapp/frontend/dist`, поэтому его готовые файлы намеренно включены в Git. Для обычного серверного запуска Node.js не требуется.
